# ADR-037: Developer posts as they stand on Spectrum, pictures included

- Status: accepted
- Date: 2026-11-10
- Deciders: owner ("we should be replicating the post (images too) as closely as possible. It should be easy to read and beautiful", 2026-11-10; asked whether to publish CIG's pictures on the live site, "Yes, publish them"), Claude Code session 2026-11-10
- Amends: ADR-027 (what the Spectrum worker reads), ADR-032 and ADR-035 (which deferred the pictures to this record), ADR-009 (a new local-only media folder, `fixtures/spectrum-media/`), spec 03's "Dev tracker UI" note

## Context

The developer tracker showed each post as the search answer carries it (ADR-027): plain text, split into paragraphs. On Spectrum the same post has headings, bold and italic words, links, quotes of other posts, lists and pictures. The owner asked for the post reproduced as closely as possible, pictures included, in the folded card ADR-035 gave it.

What Spectrum's web app reads for a thread page, probed anonymously on 2026-11-10 with the project User-Agent (`POST /api/spectrum/forum/thread/nested`, body `{"slug", "sort": "votes", "target_reply_id"}`, the same headers as the search): the thread, its opening post and one page of its replies, nested as Spectrum nests them, each post with its `content_blocks`. A block is `text` (a Draft.js raw document: blocks of type `unstyled`, `header-one`, `unordered-list-item`, `ordered-list-item`, `blockquote`, `code-block`, each with `inlineStyleRanges` of `BOLD`, `ITALIC`, `UNDERLINE`, `CODE` and `entityRanges` into an entity map of `LINK`, `MENTION` and `EMOJI` entities), `image` (uploads: `upload:<id>` with the picture's address at its uploaded size on `theverse.robertsspaceindustries.com` and its width and height) or `quote` (the quoted post's own content blocks and the quoted member). Every post also carries `lexical_content`, null today: the editor Spectrum's redesign announcement says is coming. One answer is one page: the "Spectrum Redesign" thread has 206 replies and the answer holds 25 top-level ones with their first children; `target_reply_id` centres the page on a reply, which is how Spectrum opens a deep link, and a targeted request answered with the reply and its neighbours.

The constraints: Spectrum is one request every five minutes per endpoint, thirty minutes of backoff on any non-200, never a sign-in (CLAUDE.md section 9). Content items are append-only; an edit is a new revision (section 5). Unknown shapes halt (section 5). Pictures are never hotlinked and never served by the app server (ADR-009, CLAUDE.md section 2); they are copied, built into web copies and published to the CDN (ADR-034). The design system has no new colours, faces or tokens for this (section 7). The pack holds 518 posts across 266 threads; 127 threads hold only an opening post, 139 hold replies as well, 351 replies in all.

## Decision

| Concern | Choice | Reason |
| --- | --- | --- |
| Where the post's content comes from | The thread endpoint, read by a step of `workers/poll-spectrum` after the search (`src/threads.ts`): one request per page, five minutes apart within and across threads, the same anonymous headers and User-Agent as the search. A thread's posts on record are read page by page: the first request targets the oldest reply wanted (the thread's top when only the opening post is wanted), each later one the next reply still missing; the thread is done when every post on record was found, or a page brought nothing wanted, in which case the rest is recorded as missing and keeps the search's text. Twelve pages a thread at most | The one endpoint that has the blocks; the deep-link target is how the app itself reaches a reply on a later page; a page that brings nothing wanted says the rest is not where Spectrum pages to |
| What a scheduled run reads | The threads of the posts it just collected, up to three (`SCHEDULED_THREADS`), after the search, within the news workflow's twenty minutes. `--threads <n>` reads up to n threads due anywhere on the pack: the backfill, run locally in the background | The brief's rule, so CI and a local backfill never write the same threads; a new post waits at most a run for its own content |
| Resumability and what one error costs | The pack, `fixtures/spectrum/thread-state.json` (per thread: slug, when, requests, the posts found, the posts missing) and `fixtures/spectrum/uploads.json` (every picture's address, size, post and thread) are saved after each thread. A thread is due when a shown post on record is in neither its found nor its missing list. A non-200 logs the backoff, waits thirty minutes and asks again; three in a row end the run. An unknown block type, an unknown Draft.js block type, or a post with `lexical_content` and no `content_blocks` halts the run with the block in the error, and nothing from that thread is written | A backfill of some three hundred requests at five minutes each is a day and a half; it must pick up where it stopped. ADR-027's "a run with an error writes nothing" is kept per thread, the unit a request belongs to |
| The parser | `src/blocks.ts`: `content_blocks` to HTML within an allowlist and nothing else: `p`, `strong`, `em`, `a` (an http(s) `href`, `target="_blank" rel="noopener noreferrer"`), `blockquote`, `ul`, `ol`, `li`, and `img` carrying only `data-upload="<id>"`, `width`, `height` and an empty `alt`, never a source. Text is escaped; every attribute is written by the parser, none copied. Headings become bold paragraphs, soft line breaks and code-block lines separate paragraphs (no heading, `br` or `pre` in the allowlist); underline, strikethrough and code keep their text; a mention and an emoji shortcode are their text; a quote is a blockquote opening with the quoted member's name in bold. Draft.js ranges are cut in Unicode code points, not UTF-16 units: `convertToRaw` measures offsets with `UnicodeUtils.strlen`, so an astral character (an emoji pasted as a character) counts once; cutting in UTF-16 units would shift every range after it. `withinAllowlist` checks the output and the tests run it on every post of the committed samples | Sanitized by construction rather than by a second pass; the brief's allowlist; the only correct reading of Draft.js's offsets (the brief said UTF-16, which Draft.js does not write) |
| The revision | The step puts the item again with the new `body_html` and, for the summary, the post's first line of text; the store revises when the body differs and leaves an unchanged post alone. Everything else on the row (url, title, time, author, thread) is as the search wrote it | CLAUDE.md section 5: append-only, the latest revision shows |
| The pictures | `scripts/media/fetch-spectrum.ts` copies each upload a shown post names, at the size it was uploaded, into git-ignored `fixtures/spectrum-media/` with a committed `sources.json` (upload id, file, the post's page, address, type, size, SHA-256, time), one request every five seconds with the project User-Agent and the contact address, never for a post under takedown. `scripts/media/prepare.ts` writes WebP copies at 1920, 1280, 960 and 640 wide, never upscaled, under `/media/spectrum/<id>-<width>.webp` and a `spectrum` entry in the media manifest (`SpectrumImage` in `packages/schema/media.ts`) keyed by the upload id. They publish to the Blob store with the rest of the media (ADR-034) | The same path as every other CIG picture the site shows (ADR-009, ADR-029); RSI's host, so RSI's spacing |
| How the site shows a picture | `apps/web/lib/dev-posts.ts` `renderBody`: each `img` with an upload id becomes a plate across the card, the picture's web copies from the manifest (`media().spectrumUpload(id)`, `srcset` and `sizes` for the card's width, lazy) with the credit under it as a label linked to the post; a picture not yet copied is the same frame with the caption "Picture on Spectrum, not yet copied here" and the credit, never a hotlink. The card and `excerptOf` are unchanged: the excerpt reads the stored body, where a picture is nothing. `.dev-post-body` in `globals.css` gains rules for lists and for the plate (`dev-post-plate`), from the existing tokens: the card radius, the surface, the soft shadow, the hairline, the caption size | A picture is a plate everywhere on the site (ADR-020); the brief's placeholder; no new colour, size or token |
| The credit | "Image: Cloud Imperium Games, via Spectrum" (`SPECTRUM_IMAGE_CREDIT`), linked to the post; a row in `docs/legal/attribution.md` | The pictures are CIG's, posted by its staff on Spectrum |
| Publishing them | Covered by the Spectrum box in `docs/legal/cig-approval.md`, which the owner ticked on his word on 2026-11-10 for the posts in full, extended on his words quoted above to the pictures in them, recorded under the box. No written confirmation from CIG is on file (ADR-019) | The owner's explicit call, as for every CIG picture the site shows (ADR-034) |

## Alternatives considered

| Option | Why not |
| --- | --- |
| Keep the search's text and add only the pictures | The pictures are in the same answer as the blocks; the owner asked for the post as it stands |
| One request per post rather than per thread page | 518 requests instead of some three hundred; a page already carries a post's neighbours |
| Sanitize Spectrum's own HTML | Spectrum sends no HTML; it sends Draft.js documents, which the site would have to render anyway |
| Headings as `h2`/`h3` and line breaks as `br` | Outside the allowlist the brief fixed; a bold paragraph reads as a heading inside a card, and the card's prose has one size (CLAUDE.md section 7) |
| Hotlink the uploads from `theverse.robertsspaceindustries.com` | ADR-009 and CLAUDE.md section 2 rule it out, as for every picture |
| Resolve a picture inside `DevPost` in `packages/ui` | The component takes HTML and knows nothing of the manifest; the app resolves and the component places |
| Read every due thread in a scheduled run | Would have CI and the local backfill revising the same pack in the same hours, with the JSON conflicts that brings |
| Cut Draft.js ranges in UTF-16 units, as the brief said | Draft.js writes code-point offsets; a post with one astral character would have every later bold word and link off by one |

## Consequences

- `workers/poll-spectrum/src/blocks.ts` and `src/threads.ts`, with tests on two committed cuts of real answers of 2026-11-10 (`fixtures/spectrum/samples/thread-nested.sample.json`, the Spectrum Redesign thread with text, image and erased posts; `thread-nested-target.sample.json`, an Ask The Devs thread with a quote block, read with a target reply). Members are cut to id and names; avatars, signatures, languages, votes, reactions and presence are stripped.
- `pnpm workers:poll-spectrum` reads threads after the search; `--threads <n>` is the backfill; `SPECTRUM_THREADS=off` skips the step. The news workflow commits `fixtures/spectrum/thread-state.json` and `uploads.json` with the pack.
- `fixtures/spectrum-media/` (git-ignored, README and `sources.json` committed), `scripts/media/fetch-spectrum.ts`, a `spectrum()` step in `prepare.ts`, `SpectrumImage` and `MediaManifest.spectrum` in the schema, `spectrumRenditionPath` and `SpectrumSource` in `scripts/media/sources.ts`.
- `apps/web/lib/media.ts` gains `spectrumUpload`; `apps/web/lib/dev-posts.ts` gains `renderBody`; the tracker and author pages render through it. `packages/ui/legal.ts` gains `SPECTRUM_IMAGE_CREDIT` and `SPECTRUM_IMAGE_PENDING`.
- The pack grows by one revision per post read, 518 rows for the backfill; the site shows the latest.
- What is not reproduced: underline, strikethrough and inline code (text kept), emoji as images (the shortcode stands, and the site draws no emoji, CLAUDE.md section 2), mentions as profile links, headings as headings, and any block kind not seen on 2026-11-10, which halts the run so it is looked at before anything is written.
- An edited post: the search reports a post edited after its thread was read (`edited_at` newer than the thread's `read_at`); the search step then keeps the thread's body on the row, unlists the post from the thread state and reads the thread again in the same run, so a staff edit never regresses a post to the search's text. A thread Spectrum answers 404 for (deleted, or its slug changed with its title) records its posts as missing and the run moves on, without a backoff.
- A post with empty `content_blocks` and no Lexical content keeps the search's text and is logged; empty blocks beside Lexical content halt like null ones. The parser's output is checked against the allowlist before any row is written, and a post that parses to nothing halts rather than blanks the row.
- A picture inside a quote block is the quoted member's, often a player's: it is neither copied nor shown nor credited to CIG; the quote carries its words. An atomic Draft.js block with an entity halts (none has been seen), an empty one is skipped.
- Two processes must never share the thread endpoint's limit: while the local backfill runs, the repository variable `SPECTRUM_THREADS` is set to `off` and the scheduled run skips its thread step (the search still runs); it is unset when the backfill is done. The news workflow's job has forty minutes, since a scheduled thread step sleeps five minutes between its requests and thirty on a refusal, and a scheduled run wants only the posts it collected, one page as a rule.
- Carried from ADR-035's audit, still deferred, as matters of the card rather than this data path: the summary's accessible name is its whole content; the time sits under a title that wraps at 390 px; the excerpt joins paragraphs with a space; an empty post keeps the "Show the whole post" cue; the Spectrum-on e2e records run only locally. Deferred from this record's audit: an injected fetch for `fetch-spectrum.ts` (it follows `fetch-covers.ts`); the opened-post records are large PNGs; a link inside a heading is kept as text; `time_modified` on a thread post is read and unused.
- A post Spectrum returns on no page it reaches (a reply deep in a long thread beyond twelve pages, or one since deleted) stays as the search's text and is listed under `missing` in the thread state; `--threads` does not retry it unless its entry is removed by hand.
- When Spectrum's new editor arrives (`lexical_content`), the step halts on the first such post, by design; reading Lexical is a decision of its own.
- The backfill of the 266 threads on record runs locally after the merge, in the background, at one request every five minutes: about 266 requests for the threads plus one more for each page a thread's replies spread over, some three hundred in all, a little over a day. The pictures are fetched and the media published afterwards (ADR-034's routine), then the pack committed.
