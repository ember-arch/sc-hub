# ADR-049: "What changed" patch pages, from a snapshot of every build

- Status: accepted (owner direction 2026-11-11)
- Date: 2026-11-11
- Deciders: owner ("next thing we should build: 'What changed this patch' pages. Stat changes between builds for every ship, part and blueprint, LIVE vs PTU … a dedicated page that compares official patch to patch, as well as current patch to PTU … beautifully designed, very easy to navigate … broken into collapsible sections … clearer and easier to reach than patch notes alone, but patch notes linked"), Claude Code session 2026-11-11
- Amends: spec 01's "Diff" note (patch pages arrive before the pipeline's `diff.json`), ADR-023 (the refresh gains a step), CLAUDE.md section 4 (no new folder; `fixtures/patches/` sits under `fixtures/`)

## Context

`docs/scope.md` planned patch pages built from the pipeline's `diff.json` (spec 01), which needs the game files on patch day and two published versions. Neither exists: the bootstrap pack holds one build, 4.10.2-LIVE.12881860.

On 2026-11-11 the Star Citizen Wiki API turned out to keep every LIVE build it has imported, back to 4.5.0-LIVE.10966564 (December 2025, twelve builds), listed at `/api/game-versions`, and to serve any record as of any of them with a `version` parameter (`/api/vehicles/<uuid>?version=4.5.0-LIVE.10966564` answers that build's figures; `filter[version]` and `game_version` are ignored). It also serves crafting blueprints (`/api/blueprints`, 1,617 in 4.10.2, none in 4.5.0). It lists no PTU build, and neither does the StarCitizenWiki scunpacked-data repository (LIVE branches only). The ship list does not nest ports (a gun inside a gimbal is missing), so a ship's loadout needs its own record.

The news pack already holds CIG's patch notes: the Spectrum posts in the Patch Notes channel for every PTU wave since 4.8 (inside the news window, ADR-031), the Hotfix Central threads, and some of RSI's official Comm-Link notes. Posts read since ADR-037 are kept as paragraphs; older ones as one run of text. The Comm-Link pages arrive with RSI's page-template filler text woven between real lines.

## Decision

| Concern | Choice |
| --- | --- |
| Data | One snapshot per build in `fixtures/patches/<build>.json`, written by `scripts/patches/fetch.ts`: every ship (its record with ports, one request each), every part of twenty types (guns, missiles, torpedoes and bombs, racks, shields, power plants, coolers, quantum and jump drives, radars, countermeasures, mining, salvage and tractor parts, EMP and interdiction; 200 to a page) and every blueprint of the build, each with the figures a comparison reads. About 300 requests a build at the client's 2.5 s spacing (CLAUDE.md section 9). Same selection as the pack: wiki placeholders, vehicles the ship matrix does not list (ADR-022) and records from another build are left out and counted; a blueprint that names no output (a `_TEMP` key) is left out |
| Figures | As the source states them, flattened to dotted paths (`speed.scm`, `armor.damage_multiplier.energy`, `vehicle_weapon.damage.burst`), never computed, rounded or renamed. Left out: identity, prose, prices, pictures and lists; figures the record states twice (min/max and minimum/maximum, the armour's flat and plural copies, "_formatted" twins, magazine µSCU, a part's power use that its power states already give); a ship's totals worked out from its fitted parts (signature, power and cooling by part type, the fitted shield's resistances), since the parts are compared as parts. A ship's loadout is the part fitted at each port that carries a part or a mount, by port path |
| File | Validated against `PatchSnapshot` (packages/schema), written as `PatchSnapshotFile`: every path, port and class stored once in a sorted `dictionary` and referred to by index, the header pretty and one record per line. 1.9 MB for 4.10.2 (5.3 MB with the paths spelled out); about 17 MB for the twelve builds. A build's file is never rewritten (CLAUDE.md section 5); `--refetch` exists for a broken file |
| Kept current | A `patches` step in the daily refresh (ADR-023), between the cargo boxes and the RSI steps: one request lists the builds, and only a build without a file is fetched. A new build costs about 25 minutes of the job's 300 |
| Comparison | `apps/web/lib/patches.ts`. A figure is changed when both builds state it and the values differ; new or gone when the other build states that figure for some entry of the same kind; otherwise the source did not record it then, and it is counted (shown in Sources), not shown. Entries are added, removed or changed; ships also by refitted port; blueprints also by ingredient. Parts are grouped in the families above |
| Words | `apps/web/lib/patch-labels.ts` names the figures readers look for ("SCM speed", "Damage per second", "Shield health") with units; any other path is named from its own words ("Vehicle weapon · heat · per shot") rather than dropped. A change is written with an arrow and the amount, and the share when the old value is not zero, in neutral ink: whether more is better depends on the figure, so no colour says so |
| Patch notes | `apps/web/lib/patch-notes.ts`. Posts are matched to a version by their titles ("[Wave 1] Star Citizen Alpha 4.10.2 PTU Patch Notes 12770507"; "4.10" is 4.10.0), each once (latest copy). Posts held as paragraphs are laid out in CIG's own sections (Testing/Feedback Focus, Features & Updates with a heading per feature, Bug Fixes & Technical with its set headings and crash tallies), Hotfix Central by dated entry; nothing is reworded. Posts held as one run of text, and RSI's Comm-Link notes, are linked, not laid out. Spectrum posts show only with `SPECTRUM_MODE` on, as every developer post does (ADR-027) |
| Links | A note line names a ship when it contains the ship's in-game name ("Drake Cutlass Black") or a name of two words or more ("Cutlass Black") as whole words; a one-word name alone ("Gladius", "Golem") is not a match. The line shows inside that ship's entry with a link to the post. Ships and parts link to their pages where the current pack lists them; a blueprint links to the part it makes |
| Pages | `/patches`: the newest LIVE build against the one before it. `/patches/<version>` for every LIVE build with one before it (an earlier build of a shared version adds its number, `4.6.0-11135423`); the newest's canonical address is `/patches`. `/patches/compare?from=&to=`: any two builds, oldest first whichever order they are picked in. `/patches/ptu`: the PTU against LIVE: a comparison when a PTU snapshot exists, until then CIG's notes for the version in testing (the newest PTU posts ahead of LIVE), the ships they name, and a statement that PTU figures are not on record. "Patches" joins the header between Components and Titles |
| Layout | Masthead with three ways in (Latest patch, PTU, Compare builds); the two builds and how many days apart, with an "Against" picker; four figures (ships, parts, blueprints, notes). A rail lists the sections with counts and the patch history; a filter narrows every entry by name without a reload and opens the folds that hold matches. Sections in CIG's order: Ships and vehicles (new, changed, no longer in the game files), Weapons and parts (one fold per family, the first two open), Crafting, Patch notes (newest post open), Sources. Each entry is one line (name, maker or size and grade, the two changes that moved most) that opens on its figure table grouped (Flight, Shields, Armour …), its refitted ports and the note lines that name it; past forty entries a block folds the rest. Native `details`, no animation (CLAUDE.md section 7) |

## Alternatives considered

| Option | Why not |
| --- | --- |
| Wait for the pipeline's `diff.json` (spec 01) | Needs the game files on patch day and a second published version; the owner asked for the pages now, and the wiki already holds a year of builds |
| Store only diffs between consecutive builds | Smaller, but any pair would be rebuilt by chaining, and an entry removed and re-added across builds is easy to get wrong; full snapshots compare any two directly |
| Gzipped snapshots | A third of the size again, but binary in git: a new build's file could not be read in review |
| Classify note lines by topic (missions, cargo, ships) | That is inferring a post's meaning (CLAUDE.md section 2); CIG's own headings are the structure |
| Colour a change green or red | More is not better for every figure (signatures, damage taken, spool); colour would claim a judgement the data does not make |

## Consequences

- PTU stat changes appear when a PTU snapshot exists: from the pipeline on patch day (spec 01, `source: "pipeline"`), or from the wiki if it ever lists a PTU build, which the fetch picks up unchanged. Until then the PTU page carries notes only, and says so.
- The wiki API's own import changes can look like game changes (a field it began to record shows as "not recorded" and is left out; a unit it changed would show as a change). The Sources section says the figures are the wiki's.
- The comparison reads twelve snapshots at build time. `/patches/compare` is the only page that reads them per request; `next.config.ts` traces `fixtures/patches/*.json` for `/patches/**` only.
- Spec 01's ship-page "Changed in this version" section can now be built from the same comparison; it is not part of this change.
